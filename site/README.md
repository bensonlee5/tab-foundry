# Docs Site (Hugo + Docsy)

This directory contains the Hugo docs app for `tab-foundry`.

Canonical docs remain in repo Markdown:

- `README.md`
- `CONTRIBUTING.md`
- `docs/`
- `reference/`
- `program.md`

Generated Hugo inputs are written to `site/.generated/`, regenerated by
`scripts/docs/sync_hugo_content.py`, and ignored by git.

On a fresh checkout, `scripts/docs/check_links.py` expects `site/.generated/`
to already match the canonical repo docs. Sync generated inputs before running
source-link validation.

Sync generated inputs with:

```bash
.venv/bin/python scripts/docs/sync_hugo_content.py
```

Validate source inputs in this order:

```bash
.venv/bin/python scripts/docs/sync_hugo_content.py
.venv/bin/python scripts/docs/sync_hugo_content.py --check
.venv/bin/python scripts/docs/check_links.py
```

Build and validate the rendered site:

```bash
npm install --prefix site
.venv/bin/python scripts/docs/sync_hugo_content.py
hugo --source site --minify --gc --destination public
.venv/bin/python scripts/docs/check_built_output_links.py site/public
```

Build locally:

```bash
npm install --prefix site
.venv/bin/python scripts/docs/sync_hugo_content.py
hugo --source site --minify --gc --destination public
.venv/bin/python scripts/docs/check_built_output_links.py site/public
```

If `scripts/docs/check_links.py` reports a generated docs route as unresolved,
rerun `scripts/docs/sync_hugo_content.py` first and then repeat the link check.

Canonical built output is `site/public/`.
